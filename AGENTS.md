# Home Ops

## Purpose

This repository declaratively manages a personal homelab. Prefer changes to the repository's source of truth over manual changes to running systems.

## Repository Map

- `nix/` defines NixOS and Home Manager configuration through a Nix flake, den, and import-tree. Hosts are declared in `nix/hosts/hosts.nix`; host-specific configuration is under `nix/hosts/<host>/`, and reusable modules are under `nix/modules/`.
- `infrastructure/` provisions underlying infrastructure with OpenTofu, including the home and remote lab environments.
- `kubernetes/` contains Talos configuration and GitOps-managed Kubernetes applications. Argo CD is bootstrapped from `kubernetes/clusters/home-argo/`; local Helm charts are under `kubernetes/infrastructure/` and `kubernetes/apps/`.
- Kubernetes components generally use local Helm charts with `Chart.yaml`, `values.yaml`, optional `templates/`, and `config.json` for Argo CD metadata. Use Kustomize only where the existing layout requires it.
- `openspec/` contains specifications and change artifacts for planned work.

## Working Rules

- Inspect the relevant files and established patterns before changing them. Keep changes minimal, declarative, and limited to the requested scope.
- Do not introduce imperative deployment steps when the change belongs in Nix, Talos, Helm, Kustomize, Argo CD, or OpenTofu configuration.
- The root `flake.nix` is generated by flake-file. Do not edit it directly; update its source declarations and run `nix run .#write-flake` when needed.
- Format Nix changes with `nix fmt`. Run the relevant deterministic validation for changed Nix, Helm, Kustomize, Kubernetes, or OpenTofu files, and report what was actually run.
- Preserve unrelated working-tree changes. Never revert or overwrite changes that are not part of the current task.
- Treat generated, vendored, ignored, and encrypted files as read-only unless the task explicitly requires them. Do not broadly inspect `.terraform/`, `*.tfstate*`, or `*.tfvars` files.
- Secrets are encrypted with SOPS and age. Follow `.sops.yaml` creation rules. Never add plaintext credentials, tokens, private keys, decrypted values, or secret contents to the repository, patches, logs, or responses.
- If asked to create a commit, use a concise scoped prefix such as `nix:`, `k8s:`, `infra/talos:`, or `build:`.

## Sandbox and Operator Handoff

This session runs inside a nono sandbox. The sandbox enforces filesystem, network, and credential capabilities. Do not bypass it, automatically widen its permissions, or treat it as a command allowlist to work around.

- Do not read, print, copy, or request raw credentials. Approved integrations may receive authentication from the environment, but credential values must remain inaccessible to the agent's work product.
- Do not use SSH, SCP, or other remote administration to connect to machines. Do not decrypt secrets or perform destructive remote operations such as infrastructure destruction, cluster deletion, or irreversible data cleanup.
- When an operation is blocked by the sandbox or requires privileged access, stop and report the exact operation, path or host, and error. State clearly that it was not performed.
- Guide the operator through the manual procedure outside the sandbox. Include prerequisites, a command or procedure using placeholders instead of secrets, expected verification, and rollback or cancellation steps.
- Do not recommend profile changes or permission allowlisting by default. Only describe a minimal additional read-only capability when the operator explicitly asks for it and the access is non-sensitive.
